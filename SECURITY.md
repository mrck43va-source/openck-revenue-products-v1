# Security Policy

## Reporting a vulnerability
Do not open a public issue, discussion, PR, screenshot or log containing exploitable details, credentials, API keys, tokens, MFA codes, customer data or other secrets. Use GitHub private vulnerability reporting when available, or the established private owner/support channel.

Include the affected component/version, safe reproduction steps, expected vs actual behavior, impact, and any non-destructive mitigation.

## Safe research boundaries
Do not access data that is not yours, exfiltrate private data, perform destructive or denial-of-service testing, socially engineer users, retain/publish secrets, or pivot into unrelated systems.

Critical/high unresolved findings block production release. If a secret is exposed, treat it as compromised, rotate/revoke it through the proper provider, preserve evidence, and follow the OpenCK Incident Response, Breach & Legal Hold Runbook.
